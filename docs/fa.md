# معرفی فارسی

**woocommerce-mcp** یک سرور متن باز بر پایه Model Context Protocol است که به کلاینت ها و ابزارهای سازگار با MCP اجازه می دهد یک یا چند فروشگاه ووکامرس را از طریق REST API مدیریت کنند. با آن می توان کاتالوگ محصولات را مرور کرد، سفارش ها را پیگیری کرد، مرجوعی ثبت کرد، قیمت و موجودی را به صورت گروهی تغییر داد و گزارش فروش گرفت.

این سرور در [MCP Registry رسمی](https://registry.modelcontextprotocol.io/v0/servers?search=io.github.sadrmanesh/woocommerce-mcp)، [Glama](https://glama.ai/mcp/servers/sadrmanesh/woocommerce-mcp) و [mcpservers.org](https://mcpservers.org/servers/sadrmanesh/woocommerce-mcp) ثبت شده است.

## ویژگی های اصلی

- **چند فروشگاه در یک سرور:** هر فروشگاه کلید و تنظیمات جداگانه خودش را دارد و در هر درخواست می توان فروشگاه را انتخاب کرد.
- **امن به صورت پیش فرض:** فروشگاه ها تا وقتی اجازه نوشتن داده نشود فقط خواندنی هستند. هر تغییر اول به صورت پیش نمایش برگردانده می شود و فقط بعد از تایید اعمال می شود.
- **گزارش تغییرات:** هر تلاش برای نوشتن با جزئیات کامل در یک فایل ثبت می شود. هر پیش نمایش یک شناسه `previewId` دارد. اگر این شناسه همراه `confirm: true` فرستاده شود، سرور بررسی می کند که آرگومان ها همان آرگومان های پیش نمایش باشند و در غیر این صورت درخواست را با خطای `preview_mismatch` رد می کند. همین شناسه در گزارش ثبت می شود تا هر تغییر اعمال شده به پیش نمایش خودش وصل باشد.
- **تشخیص پیش نمایش کهنه:** ابزارهایی که تغییر را از داده فروشگاه حساب می کنند، مثل افزایش ده درصدی قیمت، مقدار نهایی را همان موقع پیش نمایش حساب می کنند. پیش نمایش در بخش `preconditions` مقدار فعلی (`before`) و مقدار جدید (`after`) هر رکورد را نشان می دهد و `previewId` یک بخش دوم می گیرد که اثر انگشت همان داده هاست. موقع تایید، سرور همان داده ها را دوباره می خواند و اگر چیزی عوض شده باشد، مثلا قیمت در این فاصله تغییر کرده باشد، درخواست را با خطای `stale_preview` رد می کند و چیزی به فروشگاه نمی فرستد. این بررسی فقط تغییر داده هایی را می بیند که نوشتن از آن ها حساب شده است، نه هر تغییر همزمان در فروشگاه، و قفل هم نیست. جزئیات در [نوشتن امن](safe-writes.md#stale-previews) آمده است.
- **مرجوعی و عملیات گروهی:** مرجوعی کامل یا جزئی، ویرایش تا 100 محصول در یک مرحله و تغییر درصدی یا ثابت قیمت ها.
- **تحلیل فروش:** فروش روزانه، هفتگی و ماهانه، میانگین ارزش سفارش، پرفروش ترین محصولات و گزارش کمبود موجودی که متغیرهای محصول را هم بررسی می کند.
- **کوپن و تخفیف:** گزارش عملکرد کوپن ها، ویرایش و حذف کوپن و زمان بندی حراج برای گروهی از محصولات.
- **مشتریان و دسته بندی آن ها:** دسته های مشتریان ویژه، وفادار، یک بار خرید و در خطر ریزش، همراه با امکان پنهان کردن اطلاعات شخصی.
- **ارسال سفارش:** یادداشت سفارش، کد رهگیری مرسوله و تکمیل سفارش در یک مرحله با اطلاع رسانی به مشتری.
- **وب هوک:** مدیریت وب هوک های فروشگاه و دریافت رویدادهای امضا شده که به صورت منبع MCP قابل خواندن هستند.
- **حمل و نقل و مالیات:** مشاهده مناطق ارسال، روش های ارسال، نرخ ها و کلاس های مالیات.
- **کنترل ابزارها:** فهرست مجاز و ممنوع ابزارها برای کل سرور یا هر فروشگاه.
- **ملاحظه فروشگاه:** محدودیت نرخ درخواست، تلاش دوباره با فاصله افزایشی و کش اختیاری برای خواندن.
- **آماده اجرای راه دور:** اتصال HTTP با توکن یا OAuth 2.0، همراه با Docker و بررسی سلامت سرویس.
- **قابل مشاهده:** پشتیبانی از OpenTelemetry برای ردیابی هر درخواست.

## شروع سریع

</div>

```bash
WOOCOMMERCE_URL=https://store.example.com \
WOOCOMMERCE_CONSUMER_KEY=ck_... \
WOOCOMMERCE_CONSUMER_SECRET=cs_... \
npx -y @sadrmanesh/woocommerce-mcp
```

<div dir="rtl" markdown>

برای نصب سراسری از `npm install -g @sadrmanesh/woocommerce-mcp` استفاده کنید. نام فرمان بعد از نصب `woocommerce-mcp` است.

ایمیج داکر هر نسخه هم برای `linux/amd64` و `linux/arm64` در GitHub Container Registry منتشر می شود: `docker pull ghcr.io/sadrmanesh/woocommerce-mcp:0.5.0`. برچسب های `X.Y.Z`، `X.Y` و `latest` در دسترس هستند. بسته npm در GitHub Packages هم منتشر می شود و راه نصب آن در [روش های نصب](install.md#github-packages) آمده است، اما مخزن اصلی همچنان npmjs.com است.

کلید REST API را از مسیر WooCommerce > Settings > Advanced > REST API بسازید. تا وقتی فروشگاه فقط خواندنی است کلید Read کافی است.
